Zephyr RTOS 入門

手錶、手環、藍牙耳機裡面通常不是跑 Linux，而是一顆很小的微控制器，上面跑一個「即時作業系統」（RTOS）。Zephyr 是其中最完整的一個開源 RTOS。這頁從「為什麼需要 RTOS」講起，再介紹執行緒、排程、中斷、同步、Devicetree、藍牙省電，最後教你怎麼寫第一個程式，每個主題都有可以動手玩的動畫。

右下角可以暫停動畫、調整速度，點一下動畫也可以暫停。遇到不懂的詞，可以查最後的名詞小辭典。

Basics基礎觀念：微控制器與 RTOS

1微控制器：一顆晶片就是一台小電腦

電腦和手機用的是「處理器」，記憶體、儲存空間都是另外的晶片，跑 Windows、Linux、Android 這種大型作業系統。手錶、遙控器、家電裡用的是微控制器（MCU）：處理器、記憶體、快閃記憶體、計時器、各種接腳全部做在同一顆晶片裡，便宜又省電。

64 MHz常見藍牙晶片的時脈（手機約 3000 MHz）
256 KBRAM（手機約 8 GB，差 3 萬倍）
1 MB放程式的快閃記憶體
幾 µA睡眠時的電流，一顆鈕扣電池能撐幾個月
數字以 Nordic nRF52840 為例。資源這麼少，Linux 根本放不進去，所以需要一個非常小的作業系統。

2沒有作業系統：一個大迴圈

最簡單的寫法是不用作業系統，main() 裡面寫一個永遠不會結束的迴圈，依序做每一件事：讀感測器、畫畫面、處理藍牙、檢查按鈕，做完再從頭來。這叫超級迴圈（super loop）。

問題是：每件事都要排隊。如果畫畫面要花 10 ms，你剛好在畫畫面的時候按下按鈕，就要等畫完、等藍牙處理完，才輪到「檢查按鈕」。事情越多，反應越慢。

3RTOS：重要的事先做

RTOS（即時作業系統）把程式拆成好幾個獨立的執行緒，每個有自己的優先權。按鈕一按下，硬體發出中斷，RTOS 馬上暫停正在畫畫面的執行緒，先處理按鈕，處理完再回去接著畫。

「即時」不是指「很快」，而是指「可以保證多久之內一定會處理」。對手錶來說，這代表按鈕一定很快有反應、心率資料一定不會漏掉。

4Zephyr 是什麼

Zephyr 是 Linux 基金會管理的開源 RTOS（Apache 2.0 授權），Intel、Nordic、NXP、Google 等公司一起開發。它不只是一個排程核心，還內建了藍牙、網路、USB、檔案系統、感測器、顯示器等驅動和協定，支援幾百種開發板，從 ARM Cortex-M、RISC-V 到 ESP32 都可以跑。

它的設計很多地方學 Linux：用 Devicetree 描述硬體、用 Kconfig 選功能、用 CMake 編譯。一開始比較難上手，但同一份程式比較容易換到別的板子上。

  • Nordic nRF Connect SDK：Nordic 官方的藍牙開發套件，就是建立在 Zephyr 上。
  • ZSWatch：一支開源的 Zephyr 智慧手錶，用 nRF5340。
  • Google Chromebook 的嵌入式控制器（EC）韌體也改用 Zephyr。

Threads & scheduling執行緒與排程

每個執行緒（thread）就像一個獨立的小 main()，有自己的程式和自己的堆疊（stack）。CPU 一次只能跑一個，排程器（scheduler）負責決定現在輪到誰。

Zephyr 的規則很簡單：永遠跑「已就緒」裡面優先權最高的那一個。要注意，Zephyr 的優先權是數字越小越優先（FreeRTOS 剛好相反）。執行緒在等東西的時候（例如 k_msleep() 睡覺、等按鈕訊號），就不算就緒，讓給別人跑。

  • 搶占式（priority ≥ 0）：比較優先的執行緒一就緒，馬上搶走 CPU。
  • 協作式（priority < 0）：一旦開始跑，就不會被其他執行緒搶走，直到它自己讓出來（睡覺、等待或 k_yield()）。適合一段不想被打斷的工作。
  • 時間切片（CONFIG_TIMESLICING）：同樣優先權的執行緒，每跑一小段時間就換下一個，不會有人一直霸佔。
  • 實心：正在跑
  • 細線：已就緒，在等 CPU
  • ▼ 有新工作
四個執行緒：按鈕（優先權 1）、畫面（5）、上傳和記錄（都是 8）。「上傳」和「記錄」是很長的背景工作。切換上面的按鈕，比較按鈕要等多久才被處理，以及兩個背景工作怎麼分 CPU。

在 Zephyr 裡建立一個執行緒，最簡單是用 K_THREAD_DEFINE，開機時就會自動開始跑：

#include <zephyr/kernel.h>

void upload_thread(void)
{
    while (1) {
        send_data_to_phone();      /* 很長的工作 */
        k_msleep(1000);            /* 睡 1 秒，這段時間把 CPU 讓給別人 */
    }
}

/*               名字        堆疊大小  進入點          三個參數          優先權 選項 延遲 */
K_THREAD_DEFINE(upload_tid, 1024, upload_thread, NULL, NULL, NULL, 8,     0,   0);
進階：執行緒的四種狀態
  • 執行中（running）：CPU 正在跑它，同一時間只有一個。
  • 就緒（ready）：隨時可以跑，只是在排隊等 CPU。
  • 等待中（pending）：在等某件事，例如睡覺時間到、號誌、佇列有資料。等到之後回到就緒。
  • 暫停（suspended）：被 k_thread_suspend() 停下來，要 k_thread_resume() 才會回來。

沒有任何執行緒就緒的時候，Zephyr 會跑一個優先權最低的 idle 執行緒，它的工作就是讓 CPU 進入睡眠省電（見計時與省電）。每個執行緒都有自己的堆疊，堆疊給太小會溢位、當機；開 CONFIG_THREAD_ANALYZER 可以看每個執行緒實際用了多少。

Interrupts中斷：硬體喊「有事！」

按鈕按下、序列埠收到一個字、計時器到點，硬體會送出中斷。CPU 會立刻停下手上的事（不管是哪個執行緒），跳去執行一小段專門的程式，叫中斷服務常式（ISR），做完再回去。中斷比任何執行緒都優先。

ISR 的黃金規則：越短越好。ISR 在跑的時候，同等級的其他中斷只能排隊。如果在 ISR 裡做很久的事，其他硬體的資料就可能來不及收而遺失。正確做法是：ISR 只做「記下來、通知別人」，例如 k_sem_give() 給一個號誌，真正的工作交給執行緒去做。

  • 序列埠 ISR（收一個字）
  • 按鈕的處理
  • 其他工作
  • ✕ 來不及收、遺失
序列埠每 2.5 ms 收到一個字，硬體只能暫存一下下，1.2 ms 內沒有被 ISR 讀走就會被下一個蓋掉。按鈕要做 7 ms 的工作。
static struct gpio_callback btn_cb;
K_SEM_DEFINE(btn_sem, 0, 1);              /* 號誌：初始 0，最多 1 */

/* ISR：只做通知，馬上結束 */
static void btn_isr(const struct device *dev, struct gpio_callback *cb, uint32_t pins)
{
    k_sem_give(&btn_sem);
}

/* 執行緒：平常在等號誌，收到才做事 */
void btn_thread(void)
{
    while (1) {
        k_sem_take(&btn_sem, K_FOREVER);  /* 沒有訊號就一直等，不佔 CPU */
        handle_button();                  /* 花時間的工作放這裡，可以被中斷打斷 */
    }
}
K_THREAD_DEFINE(btn_tid, 1024, btn_thread, NULL, NULL, NULL, 1, 0, 0);
進階：工作佇列（work queue）

如果不想為每件小事都開一個執行緒，可以用 work queue：在 ISR 裡呼叫 k_work_submit(&my_work)，Zephyr 內建的「系統工作佇列」執行緒會幫你把 my_work 的函式跑完。很多驅動都用這招把 ISR 的工作往後延。另外要記得：ISR 裡不能呼叫會「等待」的函式，例如 k_msleep()、k_mutex_lock()；k_sem_take()、k_msgq_put() 要用 K_NO_WAIT。

Semaphore, mutex & priority inversion同步：號誌、互斥鎖與優先權反轉

很多執行緒會共用同一個東西，例如同一條 I²C 匯流排上的感測器。如果兩個執行緒同時去讀，資料就會亂掉。所以要有一把「鎖」：拿到鎖的人才能用，用完放回去，其他人要排隊。

  • 號誌（k_sem）：一個計數器，give 加一、take 減一，減到 0 就要等。常用來「通知」（上一節的按鈕），ISR 也可以 give。
  • 互斥鎖（k_mutex）：專門用來「保護共用資源」的鎖，只有拿鎖的人能解鎖，而且有優先權繼承。

為什麼要有優先權繼承？看下面這個有名的問題：低優先權的 L 先拿到鎖；高優先權的 H 也要用，只好等 L。這時中優先權的 M 跑出來，它比 L 優先，就把 L 搶掉一直跑。結果 H 被一個跟鎖完全無關的 M 卡住，這叫優先權反轉。1997 年 NASA 火星探路者號就是因為這個問題一直重開機。

  • 實心：正在跑
  • 上緣有粗線：拿著鎖
  • 在等鎖
K_MUTEX_DEFINE(i2c_lock);

void read_sensor(void)
{
    k_mutex_lock(&i2c_lock, K_FOREVER);
    i2c_read(...);                 /* 這段同時只有一個執行緒能進來 */
    k_mutex_unlock(&i2c_lock);
}

Message queue訊息佇列：把資料從一邊交給另一邊

心率感測器每 100 ms 產生一筆資料，藍牙執行緒負責把它送到手機。兩邊的速度不一定一樣：藍牙偶爾會忙一下（例如在重新連線）。中間放一個訊息佇列（k_msgq），就像一條輸送帶，生產的一端放進去，消費的一端拿出來，暫時處理不完的先排在上面。

佇列的長度是固定的（開機時就配好記憶體）。佇列滿了，新資料就放不進去，只能丟掉或等待。所以要依照「最壞的時候會卡多久」來決定佇列要多長。

感測器每 100 ms 放一筆。藍牙處理一筆的時間超過 100 ms，平均就跟不上，佇列再長都會滿；低於 100 ms 但偶爾會忙，佇列就要夠長，才撐得過忙的那 0.8 秒（大約 8 筆）。
struct hr_sample { uint16_t bpm; uint32_t time; };
K_MSGQ_DEFINE(hr_q, sizeof(struct hr_sample), 8, 4);   /* 最多排 8 筆 */

/* 感測器那邊（ISR 也可以）：不等待，滿了就丟 */
if (k_msgq_put(&hr_q, &s, K_NO_WAIT) != 0) {
    dropped++;
}

/* 藍牙執行緒：沒資料就等 */
k_msgq_get(&hr_q, &s, K_FOREVER);
send_over_ble(&s);

Timers, ticks & tickless idle計時與省電：沒事就睡覺

手錶一天大部分時間都在「等」：等下一秒更新時間、等手腕抬起來。CPU 在等的時候，就應該進入睡眠，電流可以從幾 mA 降到幾 µA，差一千倍。

傳統的 RTOS 用一個固定的系統 tick 計時：計時器每 10 ms（100 Hz）或 1 ms（1000 Hz）叫醒 CPU 一次，看看有沒有誰的時間到了。就算沒事做，也每秒被叫醒幾百次。Zephyr 預設是 tickless：直接算出「下一件事在什麼時候」，把計時器設到那個時間，中間一覺睡到底。

傳統 tick 頻率
程式每 500 ms 醒來做 2 ms 的事（k_msleep(500)）。電流是粗估：睡眠 3 µA、醒著 3 mA、每次被 tick 叫醒約 20 µs。圖上把很短的尖峰畫寬了，才看得到。

要固定時間做一件事，可以用 k_timer。注意 timer 到點時的函式是在中斷裡跑的，一樣要很短：

void tick_fn(struct k_timer *t) { k_sem_give(&redraw_sem); }   /* 中斷裡：只通知 */
K_TIMER_DEFINE(clock_timer, tick_fn, NULL);

k_timer_start(&clock_timer, K_SECONDS(1), K_SECONDS(1));   /* 1 秒後開始，之後每 1 秒 */
進階：電源管理

開啟 CONFIG_PM（系統電源管理）後，idle 執行緒會依照「下一件事還要多久」自動選擇睡多深：只睡一下就淺睡，等很久就深睡（關掉更多時脈）。開啟 CONFIG_PM_DEVICE 後，沒在用的周邊（螢幕、感測器、序列埠）也可以個別關電。很多 Nordic 晶片光靠 tickless 和自動睡眠，閒置時就只剩幾 µA。

DevicetreeDevicetree：把「硬體接在哪」寫在程式外面

同樣是「讓 LED 閃」，每塊板子的 LED 接在不同的腳位：nRF52840 DK 接 P0.13、STM32 Nucleo 接 PA5、Raspberry Pi Pico 接 GP25。有的板子 LED 是腳位輸出「高電位」才亮，有的是「低電位」才亮。

如果這些寫死在程式裡，換一塊板子就要改程式。Zephyr 的做法是把硬體資訊寫在 Devicetree（.dts 檔）裡，每塊板子一份；程式只說「我要用叫做 led0 的那顆 LED」。編譯的時候選哪塊板子，就套用那塊板子的 Devicetree。


    
src/main.c（三塊板子都一樣，一個字都不用改）

    
#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>

static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(DT_ALIAS(led0), gpios);

int main(void)
{
    if (!gpio_is_ready_dt(&led)) {
        return 0;
    }
    gpio_pin_configure_dt(&led, GPIO_OUTPUT_ACTIVE);
    while (1) {
        gpio_pin_toggle_dt(&led);    /* 「亮」是高還是低電位，Devicetree 會幫你換算 */
        k_msleep(1000);
    }
    return 0;
}

Bluetooth Low Energy藍牙低功耗：多久醒來一次

  
手錶用的是藍牙低功耗（BLE）。它省電的秘密是：無線電大部分時間都關著，只在約好的時間點醒來一下下。Zephyr 內建完整的 BLE 協定堆疊，打開 CONFIG_BT=y 就能用。

  
    
    
  • 廣播（advertising）：還沒連線時，每隔一段時間在 37、38、39 三個頻道各喊一次「我在這裡」，讓手機找到。間隔可以設 20 ms 到 10.24 秒。

  • 連線（connection）：連上之後，雙方約好每隔一個「連線間隔」見一次面交換資料，間隔可以設 7.5 ms 到 4 秒。

    進階：GATT 服務
    
連上之後，資料用 GATT 交換：手錶提供幾個「服務」（service），每個服務有幾個「特徵值」（characteristic），手機可以讀、寫或訂閱通知。例如標準的心率服務（Heart Rate Service），手機訂閱後，手錶每次量到新的心率就呼叫 bt_gatt_notify() 推過去。Zephyr 的 samples/bluetooth/peripheral_hr 就是一個完整的心率手環範例。

  






  
Getting started動手做：第一個 Zephyr 程式

  
Zephyr 用一個叫 west 的命令列工具管理原始碼、編譯、燒錄。下面以 Linux／macOS 為例（Windows 也可以，指令幾乎一樣）。詳細步驟以官方的 Getting Started Guide 為準。

  
    
    
  1. 1. 安裝 Python、CMake、Ninja 等工具，然後裝 west
    

    python3 -m venv ~/zephyrproject/.venv
source ~/zephyrproject/.venv/bin/activate
pip install west
    2. 
    
  2. 2. 下載 Zephyr 原始碼和相依套件（會下載好幾 GB，要等一下）
    

    west init ~/zephyrproject
cd ~/zephyrproject
west update
west zephyr-export
west packages pip --install      # 較舊的版本用 pip install -r zephyr/scripts/requirements.txt
    3. 
    
  3. 3. 安裝 Zephyr SDK（各種晶片的編譯器）
    

    cd zephyr
west sdk install
    4. 
    
  4. 4. 編譯範例 blinky，-b 後面是板子的名字
    

    west build -p always -b nrf52840dk/nrf52840 samples/basic/blinky
    5. 
    
  5. 5. 接上 USB，燒進板子
    

    west flash
    6.

printk 和 LOG
最簡單的除錯是 printk("hr=%d\n", hr);，從序列埠或 RTT 看輸出。正式一點用 LOG_INF()、LOG_ERR()，可以分等級、分模組開關。

    
Shell
打開 CONFIG_SHELL=y，序列埠就有一個命令列，可以打 kernel threads 看每個執行緒的狀態和堆疊用量。

    
官方範例
samples/ 資料夾有幾百個範例：basic/threads、bluetooth/peripheral_hr、drivers/display、subsys/display/lvgl，從範例改起最快。

    
找板子名字
west boards 會列出所有支援的板子。官方文件的 Supported Boards 頁也有每塊板子的接腳和功能。

  






  
Zephyr vs. FreeRTOS和 FreeRTOS 比較

  
FreeRTOS 是另一個很有名的開源 RTOS，現在由 Amazon 維護（MIT 授權）。它的核心非常小，只負責執行緒（它叫 task）、佇列、號誌、計時器；藍牙、網路、驅動通常用晶片廠商的 SDK 或另外找。觀念和 Zephyr 幾乎一樣，只是名字不同：

  

    

      
做什麼ZephyrFreeRTOS

      
        
建立執行緒K_THREAD_DEFINE、k_thread_create()xTaskCreate()

        
睡一下k_msleep(100)vTaskDelay(pdMS_TO_TICKS(100))

        
號誌k_sem_give() / k_sem_take()xSemaphoreGive() / xSemaphoreTake()

        
互斥鎖k_mutex_lock()xSemaphoreCreateMutex() + Take

        
訊息佇列k_msgq_put() / k_msgq_get()xQueueSend() / xQueueReceive()

        
軟體計時器k_timer_start()xTimerCreate() + xTimerStart()

        
在 ISR 裡呼叫同一個函式，參數用 K_NO_WAIT要改用 ...FromISR() 版本

        
優先權數字越小越優先數字越大越優先

      
    

  

  

    

      
ZephyrFreeRTOS

      
        
定位完整的作業系統：核心 + 驅動 + 協定 + 工具精簡的核心，其他自己組

        
內建功能藍牙、Wi-Fi、TCP/IP、USB、檔案系統、Shell、LOG、電源管理、韌體更新核心本身沒有；FreeRTOS-Plus 另有 TCP、MQTT 等函式庫

        
硬體設定Devicetree + Kconfig，換板子不用改程式FreeRTOSConfig.h，腳位寫在程式或廠商 SDK 裡

        
核心大小最小約 8 KB 起最小約 5–10 KB

        
學習曲線比較陡：要先懂 west、CMake、Devicetree平緩：加幾個 .c 檔就能用

        
誰在用Nordic nRF Connect SDK、ZSWatch、Chromebook ECESP-IDF（ESP32）、STM32Cube、AWS IoT、PineTime 的 InfiniTime

        
授權Apache 2.0MIT

      
    

  

  

    
比較適合 Zephyr
用 Nordic 晶片做藍牙產品（手錶、手環、感測器）；需要很多協定（藍牙 + USB + 檔案系統）；想要同一份程式跑在不同板子上。

    
比較適合 FreeRTOS
用 ESP32、STM32 而且廠商 SDK 已經包好 FreeRTOS；功能單純、想要越小越好；想先快速學會 RTOS 的基本觀念。

Glossary名詞小辭典

  

    

      
微控制器（MCU）
處理器、記憶體、快閃記憶體、周邊都做在同一顆晶片裡的小電腦。

      
RTOS
即時作業系統。重點不是快，而是能保證事情在多久之內一定被處理。

      
超級迴圈
不用作業系統，main 裡一個無限迴圈依序做每件事的寫法。

      
執行緒（thread）
一段獨立執行的程式，有自己的堆疊和優先權。FreeRTOS 叫 task。

      
排程器
決定現在輪到哪個執行緒用 CPU 的那部分作業系統。

      
優先權
執行緒的重要程度。Zephyr 數字越小越優先，負數是協作式。

      
搶占（preemption）
比較優先的執行緒一就緒，就把正在跑的執行緒暫停、搶走 CPU。

      
時間切片
同優先權的執行緒輪流，每人跑一小段時間就換下一個。

      
堆疊（stack）
執行緒放區域變數和函式呼叫資訊的記憶體，每個執行緒各一塊，大小要事先給。

      
中斷（interrupt）
硬體發出的訊號，讓 CPU 立刻停下手上的事去處理它。

      
ISR
中斷服務常式，中斷發生時執行的那段程式，要越短越好。

      
號誌（semaphore）
一個計數器，give 加一、take 減一，到 0 就要等。常用來通知。

      
互斥鎖（mutex）
保護共用資源的鎖，一次只讓一個執行緒進入，有優先權繼承。

      
優先權反轉
高優先權的執行緒被低優先權的卡住，又被中優先權的插隊，等得比預期久很多。

      
優先權繼承
拿著鎖的執行緒暫時借用正在等它的人的優先權，趕快做完放鎖。

      
訊息佇列（msgq）
固定長度的資料排隊區，一邊放、一邊拿，用來在執行緒之間傳資料。

      
work queue
一個專門幫你跑小工作的執行緒，常用來把 ISR 的工作往後延。

      
tick
作業系統計時的基本單位，傳統做法是固定頻率叫醒 CPU 一次。

      
tickless
不固定叫醒，直接把計時器設到下一件事發生的時間，中間一直睡。

      
idle 執行緒
優先權最低的執行緒，沒人要跑的時候讓 CPU 進入睡眠。

      
Devicetree
描述板子上有哪些硬體、接在哪些腳位的文字檔，和程式分開。

      
overlay
專案自己的 Devicetree 補丁檔，用來修改板子預設的設定。

      
Kconfig
Zephyr 的功能開關系統，在 prj.conf 裡寫 CONFIG_XXX=y 打開功能。

      
west
Zephyr 的命令列工具，負責下載原始碼、編譯、燒錄。

      
GPIO
通用輸入輸出腳位，可以讀按鈕、控制 LED。

      
I²C、SPI、UART
晶片和感測器、螢幕、電腦之間常用的三種連接方式。

      
BLE
藍牙低功耗，手錶、手環和手機溝通用的無線技術。

      
廣播間隔、連線間隔
BLE 多久醒來一次喊話或交換資料，越短越快、越耗電。

      
GATT
BLE 連線後交換資料的格式，由服務和特徵值組成。

      
µA、mA
電流單位。1 mA = 1000 µA。手錶睡眠時只有幾 µA。

    

  






  
  





內容依 Zephyr Project 官方文件整理。動畫裡的時間、電流、程式大小都是為了說明而簡化的粗估值，實際數字依晶片和設定而不同。
